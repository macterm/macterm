# The session server

This file loads when you work in `server/`. The root `AGENTS.md` has the build, the architecture and the conventions.

- **The server has no pin.** `scripts/build-server.sh` builds it for macOS universal and Linux x86_64 and aarch64 (static musl, stripped). That script holds the Zig version and the flags.
  - The build key is the hash of the git objects of `server/src`, `server/build.zig`, `server/build.zig.zon` and that script, from the working tree. Tests, schema files and host scripts are not in it, so a change to them makes no new build. `zmx version` reports `1.0.1+thdxg.<key>` for people; `hello.build_key` and `session.list`'s `build_key` carry the key itself.
  - **One manifest describes a build**: `macterm-<key>-server.json` next to the tarballs (key, targets, SHA-256 of each tarball). Every script and workflow takes the targets from `build-server.sh targets` and checks a build with `build-server.sh verify <dir> [key]`, never on its own.
  - Setup installs the build for the key and copies its manifest to `Macterm/Resources/zmx/server.json`, last, as the stamp. It takes, in order: `build/server` (CI puts its own build there); a Zig build when the sources have changes that are not committed; the prebuilt from the `server-prebuilt` release; a Zig build.
  - `.github/workflows/server-build.yml` builds on `macos-26` with Xcode 26.3, because zig cannot link with Xcode 26.4 or later (zig#31658). Its Linux job `Find Prebuilt` takes the prebuilt when it exists, and the macOS job `Build` then does not run. It uploads a new build on `main` and on pull requests from this repository, and never replaces an asset. Every 6 hours, `server-prebuilt-prune.yml` runs `scripts/prune-server-prebuilts.sh`. It removes each build except the build of main's key, of the head of each open pull request, and of the last 14 days. It removes a build as a whole, and removes nothing when it cannot find one of those keys.
  - The release workflows build from the commit, never from a prebuilt.
  - `build.sh` refuses a bundle whose server is not the build of the tree.
  - **The app carries a gzip build for every host target** for an install on a host, with no download: `Contents/Resources/server/macterm-<key>-<target>.gz` for `universal-macos`, `x86_64-linux` and `aarch64-linux`. The app reads the build key from the name of the macOS file (`ServerBuilds.bundledKey`); `embed-zmx.sh` names the files with the key of the installed manifest. `setup.sh` makes the Linux files next to `zmx`; `embed-zmx.sh` makes the macOS file from the signed `zmx`, so it has the app's identifier. The app's signature seals all three. `build.sh` refuses a bundle without them or with a macOS file that is not the bundled `zmx`. `build.sh` and `BundledResourcesTests` also check that each Linux file is an ELF binary for its machine.
- **The server has no v1 code.** It started as the zmx fork at upstream v1.0.1 (the `DOWNSTREAM.md` of thdxg/zmx names each change by its old patch number: 0003 is the leadership claim, 0004 the disclaim, 0010 the foreground report). Its own verbs are `server`, `connect`, `proxy` and `version`, and the hidden `__session` (the session process) and `__create-session` (tests make a session with it). Every other word goes to the `macterm` CLI (see below). v1's verbs (`attach`, `list`, `kill`, `get`, `set`, `clear`, `history`, `send`, `__daemon`) and their daemon are gone. A v1 session daemon (zmx 0.8.1) keeps running until the first v2 launch ends it by its argv (`V1Sessions`). Remote panes are sessions of the host's v2 server, and v1 sessions there keep running.
- **The leader's terminal answers the terminal queries.** While no client leads, the session's ghostty-vt terminal answers them (`Watch.answers_all`), except the OSC color reports and the kitty graphics replies. The session answers the OSC 7501 support query at all times. No byte scanner answers a query.

## The macterm CLI (design/011)

The port of the Swift CLI to Zig is in `src/cli/`. The Swift CLI stays `Resources/bin/macterm` until the swap (design/011 §3), so nothing a user sees changes until then. Run the Zig CLI as `zig-out/bin/zmx <verb>`.

- **The v1 contract is the test.** `golden/` holds the v1 grammar and output (`contract.zig`). `cli.zig` checks each ported command against `contract.json` (abstract, usage, options, arguments, subcommands), the help of each ported leaf against its `golden/help` file byte for byte, and each case of a ported verb against `cases.json`. A port issue adds its verbs to `root` and sets the `method` of its lines in `cases.input.json`.
- **Exit codes**: 0 done, 1 refused or failed, 2 no server answered, 64 a usage error (as ArgumentParser).
- **The CLI never starts the server.** `status` must fail while the app is not up.
- **Discovery** (`client.candidates`): `--socket` pins one socket. Else `MACTERM_RUNTIME_DIR` pins its `.server`. Else the folder of each build flavor, `macterm` then `macterm-debug`, as `LocalServer.runtimeDirectory` makes it. `MACTERM_SOCKET` is not read: it names the app's `control.sock`.
- The CLI says `hello` with the role `cli`, so a server of another build refuses it, and the CLI exits 1 with both builds. The server's pid comes from the socket (`LOCAL_PEERPID`, `SO_PEERCRED`), not from the server.
- **Output is streaming** (`writerStreaming`): a positional writer writes at offset 0 of a file that a shell appends to.

## The roaming link (design/009, issue 0201)

A UDP link that carries a host's frames after sleep or a network change, with no login. The ssh connection stays the way in and the standby. The link is built in three parts. Only the app part changes what a user sees.

- **The packet layer is the first part** (`server/src/link/packet.zig`, `Macterm/Link/LinkPacket.swift`). It has no cipher of ours: ChaCha20-Poly1305 from the Zig standard library and CryptoKit. A packet is `key_id u32`, `counter u64` (bit 63 is the direction), the sealed payload and the 16 byte tag. The nonce is 4 zero bytes and the counter. The 12 byte header is the associated data.
- **The roam rule:** `open` says if a counter is the newest. A caller may move the peer's address only on a packet that authenticates *and* is the newest. The replay window is 64 packets. It moves only after the tag is good.
- **A packet that does not authenticate gets no reply.** The two sides must make the same bytes: the vector in `packet.zig` is checked again in `LinkPacketTests`. `zig build fuzz-link --fuzz=…` fuzzes the parser, and CI runs it (`server.yml`).
- **The host part is the second part** (`server/src/link/host.zig`, `stream.zig`, protocol level 3). `link.open {secret, key_id}` makes the server open a UDP port (first free of `MACTERM_LINK_PORTS`, default 60001-60999) and answers `{port}`. The client makes the 32 byte key and sends it in this one request, over ssh. A result and an event never hold a secret, so the host cannot send it back. `MACTERM_LINK=off` in the server's environment turns the link off (`unavailable`). `link.close {key_id}`, 60 s with no authenticated packet at the start, and 24 h of silence end a link. `link.close` works from any connection, and a full table ends the link that heard last. The end of the opening ssh connection does not end it: the link must outlive ssh, which is the case that roaming serves. A link sends nothing after 30 s of silence (`quiet_ms`) and sends again after its next authenticated packet. A key that equals another link's key is refused, because the nonce is the counter alone. The client must make a new key for each `link.open`: the host cannot see a key reused after a restart, and a reused key repeats nonces. A bad `MACTERM_LINK_PORTS` turns the link off. The socket closes with the last link. A link's client must say `hello` within 5 s, like any client. The server's hello lists the cap `udp-link`.
- **A link is an ordinary client of the server.** The host joins UDP to one end of a socket pair and the server holds the other end as a peer (`Server.addPeer`, through `pending_peers`: a request cannot add to `peers` while the loop walks it). The relay, its skip-ahead and every request work on a link as on a socket. After a roam, the same peer and the same channels go on.
- **The stream under it is go-back-N** (`stream.zig`): DATA with an offset, cumulative ACK, a window of 32 KiB, a timeout that starts at 250 ms and doubles to 2 s, a keepalive ACK every 3 s. It is not R1 of design/009 (state, not bytes): the relay's skip-ahead already sends state, so the stream stays simple. `write` takes less when 256 KiB wait, and the host stops reading the socket pair.
- **Cost control:** a packet goes to the link that its `key_id` names. A source that is not the link's current client pays one token for its AEAD check (400 tokens, 200 a second). A packet that fails gets no reply.

## Session daemons and macOS attribution (#419)

macOS attributes work that needs privacy permission (Local Network, TCC) to the *responsible process* of a process. The value is fixed when the process starts, and the process inherits it from its parent.

- Because of this, the whole tree of a pane belonged to the Macterm that created its session. It belonged to nothing after that Macterm quit. Every process that survives becomes responsible for itself. A new start of Macterm that connects again over the zmx socket never attributes it again, because a connect is not a fork.
- From then on, macOS judged each pane program by its own identity. For anything that Apple did not sign, this meant `EHOSTUNREACH` on the local subnet, with no prompt.
- The fix: the server starts each session process with one `posix_spawn` that has `responsibility_spawnattrs_setdisclaim` (`spawnSession` in `server.zig`). The session is its own responsible process from the first instant. Every program in the session belongs to **it** for the whole life of the session, whatever happens to the app.

- **The daemon has the signature of the app itself** (`scripts/embed-zmx.sh`). It uses the certificate of the app *and* the bundle identifier of the app. The certificate is the release certificate in CI, and it is ad-hoc on your Mac.
  - macOS identifies a responsible process by the identifier in its code signature. With the identifier of Macterm, the daemon resolves to the name of Macterm, its usage descriptions and its existing grants for Local Network and TCC. One grant covers the app and every pane.
  - Any other identifier names a second thing and needs a second grant. Examples: the `zmx` of the release download, which the linker signed, and a separate "Macterm Sessions". We tried the second one. The prompt only said "zmx", because a bare binary has no LaunchServices record that gives it a name.
  - Xcode never signs a Mach-O again when it copies it into `Resources/`. An ad-hoc daemon would be a new identity at every update.
  - `build.sh` refuses a release bundle whose zmx is ad-hoc or is not `com.thdxg.macterm`. `BundledResourcesTests` pins the identifier on the zmx of the built bundle. A change in a build phase therefore cannot turn every pane prompt into a prompt for "zmx" in silence.
- Full Disk Access follows the same attribution. The programs of the daemon satisfy the own TCC requirement of the app (identifier and certificate). They inherit its FDA grant, and this stays true after the first new start.
- You cannot change responsibility afterwards (`responsibility_set_*` needs a private entitlement). The disclaim exists only as a spawn attribute. This is why the server spawns `__session` itself, with no process between, and why there is no flag for it. The responsible root must *stay* a zmx process. A trampoline that ran the shell with exec would keep the pid, but the identity that macOS evaluates would become the identity of the shell.
- **One spawn starts a session.** The spawn has `POSIX_SPAWN_SETSID`, and on macOS `POSIX_SPAWN_CLOEXEC_DEFAULT`, so the session gets only the fds of the file actions: /dev/null on 0 to 2, and its end of a socket pair on `session.spec_fd`. On Linux every fd of the server is close-on-exec. The spec is one msgpack `SessionCreate.Args` on that socket pair. The session binds its socket, starts the shell, then answers `session.ready_answer` or its error text on the same fd (`session.run`). The session stays a child of the server until the server exits (`Server.children`). The `__create-session` verb asks the server, as `connect --` does.
- A session that an older build created keeps its old attribution until you create it again. The fix takes effect for each session.
- To measure, use `responsibility_get_pid_responsible_for_pid` (a probe in C of ten lines). A Local Network prompt that nobody *answered* denies everything under that responsible process, also platform binaries. A subnet that looks dead can be a dialog that waits.
