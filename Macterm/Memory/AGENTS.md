# Project Insights

This file loads when you work in `Macterm/Memory/`. The root `AGENTS.md` has the build, the architecture and the conventions.

## Project Insights (Settings → Intelligence)

The user-facing name is **Project Insights** (the Settings section, the command Toggle Project Insights, the docs page `/docs/project-insights`, with a 301 from the old `/docs/project-memory` in the Caddyfile of macterm/website). The code, the preference keys (`macterm.memory.*`), the hotkey id `toggle_project_memory`, the `MactermKeybind` case, the storage folder `Memory/` and the DEBUG verb `project memory` keep the old name on purpose: each is stored or wired, and a rename would drop a user's keybind, a saved shortcut or their records. Each project keeps a log of the commands that finish in it. A floating glass panel on the trailing side of the window shows where the user left off, the project's Git state and the next commands to run. The code is in `Macterm/Memory/` and `Macterm/Views/ProjectMemoryPanel.swift`. The grammar for users is in `43b-project-insights.md` (in the docs of `macterm/website`).

- **macOS 26 and later only** (`ProjectMemory.isSupported`). Below it, nothing records, the command has no action, the menu item and the toolbar button are not there, and Settings lists no Intelligence pane (`SettingsPane.visible`). There is no fallback UI.
- **It needs Apple Intelligence** (`ProjectMemory.modelAvailability`, `OnDeviceModel.availability`). While the model is `.notReady` or `.unsupported`, `ProjectMemory.isEnabled` is false, so nothing records and the command, the toolbar button, the panel and the intent are off. `Preferences.projectMemory` keeps the user's value, so the feature comes back when Apple Intelligence does. Settings → Intelligence disables the switch, dims it, shows it off, and adds the reason after its description in the same caption, with the text of the On-device model row. The value is observable and read again only when the app becomes active (`refreshModelAvailability`, observer in `attach`) and when Settings → Intelligence opens, because the user turns Apple Intelligence on in System Settings. A model download that finishes while Macterm is in front shows at the next activation. There is no summary toggle (`macterm.memory.summary` is a retired key).
- **One switch, off until the user turns it on** (Settings → Intelligence → Enable Project Insights, `Preferences.projectMemory`, `macterm.memory.enabled`, `ProjectMemory.isEnabled`). A log of commands is the user's to start, never a surprise. While it is off, nothing records, `AppCommand.toggleProjectMemory` has no action (it is not in the palette or the View menu, and ⌘I is swallowed; Keymaps still lists it), and the toolbar button and the panel are not there (`ProjectMemory.showsPanel(in:)`). There is no switch for each project, and the panel has no off state. The View menu item is `ProjectInsightsMenuItem`.
- **Never store the scrollback.** An entry (`MemoryEntry`) is the command, its folder, its exit code, its time and duration, and for a failure only the last 20 lines (2 KB) of output. Every text field goes through `MemoryRedaction` first.
- **The command comes from the session's command end, never from the screen** (`CommandEnd`, the one input of `ProjectMemory.commandEnded`). The session's `end` mark (OSC 133;D) has the command line and the exit code. The command line is the shell's own text when it sent one on 133;C (`cmdline` or `cmdline_url`). Else it is the input cells of the prompt, which the session reads at 133;C, before any output, so a `clear` or a screen of output cannot take it away. The folder is the session's `cwd` (`GhosttyTerminalNSView.currentPwd`). The start is the session's `output` mark (`Pane.commandStartedAt`). A command that started before the channel attached has no start and a duration of 0. A shell with no prompt marks and no `cmdline` (macOS's `/bin/bash` 3.2, which ghostty does not inject, or `shell-integration = none`) gets no records. A command with a leading space is recorded like any other (`ProjectMemory.reportedCommand`). An end with no command is not recorded: a row with no command is noise. Never guess.
  - A surface with no session (a remote host with plain ssh shells) gives libghostty's `COMMAND_FINISHED` instead, with the command of fork patch 0019 (`ghostty_action_command_finished_s.command`), as the same `CommandEnd`. A surface on a channel ignores it for memory.
  - **A failure's output tail comes from the session, never from the screen.** The session reads it from its own terminal at the `end` mark (`output_tail`, the output cells from the `output` mark to the cursor, the cursor's row and the 19 above it at most; only for a nonzero exit code), before the shell prints its next prompt. A command that moved the cursor above the place of its `output` mark (a clear inside it) gives no tail. The recorder keeps the last 20 lines (2 KB) of it, redacted (`CommandEnd.outputTail`, `ProjectMemory.makeEntry`). A surface with no session gives no tail. Every entry is recorded at its end, so the store appends in the order of the ends (`ProjectMemoryStore.append`).
  - **A pane records once.** Every surface's channel gets the same marks, and every surface parses the same OSC 133;D, so without the rule every command was recorded twice. The pane's `PaneLink` gives the pane the marks of its counting view only (`Pane.receiveSessionMark`), and a surface with no session records only while it counts (`PaneSurface.countsOutput`).
- **What it covers** (`ProjectMemory.covers`): projects only. The pinned and scratch workspaces, the quick terminal and desktop widgets are not recorded.
- **Storage** (`ProjectMemoryStore`): `<App Support>/Memory/<project id>.json`, 500 entries, oldest first, debounced atomic writes, flushed at quit. A file that does not decode is never written over. A view reads `loadedEntries` only, after `prepare` in `.task`: a lazy load in a body would mutate observable state during the update. `AppState.removeProjectWithoutSaving` deletes a removed project's file (every removal path goes through it). `attach` prunes the files of projects removed while Macterm was not running, **never when `ProjectStore.loadFailed`**: a `projects.json` that does not decode leaves an empty list that is not the user's, and a prune against it deleted every project's memory.
- **Git** (`ProjectGit`, `GitStatusParser`): local and remote projects. Six reads: `status --porcelain=v2 --branch --show-stash` (also the changed paths), `log`, `for-each-ref refs/heads --sort=-committerdate` (the `recentBranchCount` branches with the latest commits), `worktree list --porcelain` (the worktree of each branch), the branch log (`ProjectGit.branchLogScript`, one POSIX sh script for local and remote: the main refs that exist, `origin/HEAD` resolved, then the commits of the current branch that none of them has), and the diff (`ProjectGit.diffArguments`: `git diff HEAD -U1`, staged and unstaged, in the whole repository, with no external diff and no textconv, which run programs that the repository's config names). **The diff is read only when a tracked file has changes** (`GitStatus.hasTrackedChanges`, also on the host), and never for a commit, whose subject is in the digest already. git never sends the files of `GitStatusParser.leftOutNames` (lockfiles, `.env*`, `*.env`, key files, names with `secret` or `credential`) and the files in `leftOutFolders` (folders with those words), which it gets as exclude pathspecs with `top` (a project in a subfolder reads the whole repository), and `head -c` cuts the output at `diffByteLimit` (64 KB), locally and on the host, so a large diff costs no time and no memory. `GitStatusParser.parseDiff` leaves out the same names again, binary files, a file with `PRIVATE KEY`, a file with a line longer than `diffLineLimit` (500 characters: minified or encoded text), and the last file of a cut read. It gives a deleted file one line (`deletedFileLine`) and keeps at most `diffCharacterLimit` characters of whole files. **The diff lines are not redacted** (Ethan, 2026-11-10): the diff goes only to the on-device model and is never stored, and the mask turned code such as `token: String` into noise. The secret files stay out, and the summary is redacted instead (below). It splits at each `\n` scalar, because a CRLF line end is one Swift `Character`. Untracked files are paths only. The branch log is unknown (nil), never empty, without a branch, a main ref or a finished read (its `end` line). Every git run has `core.quotePath=false`. The current branch is in the list as a row like the others, highlighted by the row alone: the accent as its fill and a bold name, with the same glyph in the same color as the other rows (no check); one style for every row keeps the ages in line, where a prominent button style padded differently. A branch row is a card row like the Suggested rows (`cardRow`: a flat fill in `MactermTheme.surface` at the failure card's 12 pt corner, dimmed while pressed by `RowButtonStyle`; the rows were glass buttons first, whose `.glass` style ignores `buttonBorderShape`), with the name and the age only, and goes to the branch in the CURRENT pane (`ProjectMemoryActions.type`): `cd "<worktree>"` typed for a branch that a worktree has checked out, or `git switch <name>` for a branch with none, so the switch is on the screen and in the shell's history, local and remote alike. The pane must have a live terminal that is not `.running`; a toast says so otherwise. A worktree path with a quote or a newline is refused with a toast. The rows opened a tab in the worktree before, which put the branch in another shell than the one the user was in. The card is the branch rows alone: no commit list, no branch line and no counts line; `recentCommits`, the counts and ahead/behind feed the digest only. The panel reads it when it shows a project; **for a local project, on every change in its git dir** (`GitDirectoryWatcher`: a directory watch on the git dir, and the common dir of a linked worktree, so a `git switch` anywhere, in a pane, an IDE or another terminal, moves the highlight within `gitReadAfterDirectoryChange`, 250 ms; the panel's own reads write nothing there, `GIT_OPTIONAL_LOCKS=0`); `gitReadAfterCommand` (300 ms) after ANY command finishes in the project while a window shows the panel for it (`ProjectMemory.panelShows`, `AppState.insightsPanelShows`, never for every command in every project), recorded or not, because a private command or an unread one moves the branch as well; 1 s after a branch row is clicked, for a remote shell that reports no command end; on app activation; and every 15 s while it is up and Macterm is active (`ProjectMemoryPanel.gitRefreshInterval`). **Only a Git state that changed restarts the summary's quiet wait**: with no summary on record every read counts as unseen, and a read of the same state restarted the 10-minute wait, so with the panel up the background summary never came. It never fetches. The panel has no refresh button and no close button. `ProjectGit.run` reads git's output through the pipe's readability handler up to its EOF, bounded by `drainTimeout`, so the tail of `git log` is never lost to a read that raced the last write. **Never run the `/usr/bin/git` shim on a Mac without the Command Line Tools**, because it opens the install dialog. `ProjectGit.executable` takes Homebrew's git, or the git in the developer directory of `xcode-select -p`, which never opens a dialog. Each run has a 5 s timeout, `GIT_OPTIONAL_LOCKS=0` and `core.fsmonitor=false` (a daemon could hold the output pipe open). Git's output pipe is read as data arrives, never with `readDataToEndOfFile`.
  - **A remote project runs the same six reads on the host through its server** (`HostCommands.gitProbeScript`, `ProjectGit.remoteStatus`): one `command.run` request over the host's one connection (`RemoteHosts.run`, 0058), with the outputs separated by `ProjectGit.recordSeparator`. It never asks for a login and opens no connection of its own: with no connection or no server up, nothing is read. The script exits 2, 3 or 4 for no directory, no git and no repository, which read as "no git state", and 0 in all other cases (the branch log fails on a detached HEAD). An unreachable host keeps the last state: a flaky link must not blank the panel. A branch with a worktree on the host is reached with `cd` typed into the current pane, because the shell is the host's.
- **Suggested** (`ProjectMemorySuggestions`, pure): with the model, the rows are its suggestions, from `OnDeviceModel.suggestCommands` (guided generation, a `@Generable` list of command and reason, in `OnDeviceModel.swift` with the rest of FoundationModels), requested right after the summary's text in the same run and stored with it. **The model chooses and orders; it never invents a command the panel will run**: a suggestion is kept only when it is a command that ran in the project (`candidates`: the latest 30, normalized, nothing trivial or masked) or one of `safeGitCommands`. **There is no fallback.** Without the model, before its first summary, or when nothing it suggested survives these checks, the section is hidden, as the summary is: a command is never suggested only because it ran recently or often. The instructions (`ProjectMemoryDigest.suggestionInstructions`) ask for a cause that the log or the Git state shows, and an empty list when there is none. `ProjectMemory.suggestedActions` is the one place that decides.
- **A Suggested row** (`QuickAction`) TYPES the command into a new split (`ProjectMemoryActions`), not into the environment as a palette `run:` does: the command was recorded from the user's shell, so it is in that shell's language. **A command with a masked secret is never offered or run** (`MemoryCommand.isMasked`): the mask would be typed in place of the secret.
- **Each window shows its own project's panel, and opens or closes it on its own.** It shows `WindowState.activeProjectID`, never the app-wide mirror. Its header shows the folder glyph of the sidebar's project row, with the color tag. Its visibility is `WindowState.projectMemoryPanelVisible`, saved as `WindowSnapshot.projectMemoryPanelVisible`, and a view reads it through `ProjectMemory.showsPanel(in:)`. A new window opens with the panel closed. A window keeps its value while the feature is off. `AppCommand.toggleProjectMemory` (default ⌘I; ghostty's own inspector is `super+alt+i`) and the CLI change the key window's value (`AppState.projectMemoryPanelVisible`). The toolbar's (i) button changes its own window's value. The restore gives the retired app-wide value (`macterm.memory.panelVisible`) once to each saved window with no value (`WindowSnapshot.adoptingLegacyPanelVisibility`). The panel floats over the panes and never resizes them.
- **The toolbar button can be hidden** (`Preferences.showProjectInsightsButton`, on by default; Settings → Appearance → Toolbar and the toolbar's right-click menu, both shown only while `ProjectMemory.isEnabled`). It hides only the button: the command and the panel still work.
- **The summary paragraph** (`ProjectMemorySummarizer`, `ProjectMemoryDigest`) is Apple's on-device model (`OnDeviceModel.stream`) over a digest of the git state and the log, never the scrollback. **It summarizes what the user has been working on, from Git first**: the digest puts the branch's own commits (on a branch with none, no commit line: the model retold "has no commits" as "no changes are present"; on the main branch or with an unknown branch log, the latest commits), the first `changedPathLimit` changed paths and the diff of the uncommitted work, within `textTokenBudget` (1,500 tokens). **The summary gets the commands only when Git shows no work** (`ProjectMemoryDigest.summaryText`, `gitShowsWork`: no commits and no changed files). The Recent list shows them, and with them in the prompt the model retold them whatever the instructions said. The suggestions get the latest 12 commands with outcome, age and the redacted failure tail. **The diff gets only the budget that the rest leaves** (`ProjectMemoryDigest.diffLines`): a whole file at a time, a file that does not fit is left out, never cut in a hunk, and a last line counts the files left out. The other branches and a clean tree are not in the digest. **With no command and no Git work there is no digest** (`ProjectMemoryDigest.init` is nil), and the panel hides the Summary section: a branch name alone made the model guess the work. **The summary talks to the user as "you"** (Ethan, 2026-11-17), with one sentence for each piece of work, from the first piece, and "you" as the subject of every sentence. That rule keeps out the sentences about "the current state of the repository", the branch and what is absent. The reply is joined into one paragraph (`ProjectMemorySummarizer.oneParagraph`), because the model put a line break after a sentence. The instructions also tell the model not to state a goal, not to describe a failure, not to suggest a next step, to name a file only when the digest lists it as changed, to say what the diff does but never call it commits (without that sentence, on a branch with no commits, the model called the diff "the latest commits"), and never to write a secret value. **The model's text and each suggestion's reason go through `MemoryRedaction.redact` before they are shown or stored** (`ProjectMemorySummarizer.redacted`), because the diff in the prompts is not redacted. While the reply streams, the panel shows it up to its last whitespace (`completeWords`), because a key that streams in a token at a time matches no rule until it is whole. **Measure a change of the wording on the real model**: a rule that names a thing to leave out can make the model write about that thing. The instructions say that the text is data. It shows only where `ProjectMemorySummarizer.isEnabled`: memory on and the model `.available`. One summary for each project, keyed by `ProjectMemoryDigest.key` (the records' ids and outcomes, the git line, the branch's own commits, the named changed paths, and `diffHash`, a hash of all of the parsed diff and not only the part that fits, because that part changes with the length of the command lines; so a newly changed file or an edit to a changed file also restarts the quiet wait below, **with no time in it**: the prompt says how long ago each command ran, so the prompt text changes as time passes and cannot be the key), so the same log never runs the model twice. A finished summary is stored in the memory file (`MemoryFile.summary`, `StoredSummary`) and seeds the summarizer at the next launch. A new digest cancels the run in flight and starts another after `debounce` (1.5 s), with the old text up until the new one streams in. **Two things write a summary, and nothing else**: `ProjectMemory.scheduleBackgroundSummary`, after a project has been quiet for `summaryQuietPeriod` (10 min after its last command, panel or no panel, so that a panel opened after a break shows the summary at once; a new command restarts the wait, and so does a Git read whose state the summary on record has not seen, `gitStateIsNews`, which is how a commit from another terminal reaches it; **a project with no summary yet gets its first one with no wait**, at the first Git read that finds a state (`ProjectMemorySummarizer.hasSummary`), because the Git state says most of it and a new project must not wait for commands; the summarizer's `debounce` still makes two reads in a row one run), and the reload button in the Summary header (`ProjectMemory.writeSummary(force:)`, which runs again for the same key). The panel never writes one itself: it `prepare`s the stored summary in its `.task` and shows it. The instructions tell the model not to say how long ago things happened, because a stored summary is read later. A failed run leaves the button; the facts below say the same.
- **The failure card shows a failure only while it is still the thing to fix** (`ProjectMemorySummary.unresolvedFailure`): the latest failed command with no later success of the same program and subcommand (`MemoryCommand.retryKey`: the words before the first option, when there are two or more, else the whole command), and with no pause of `stretchBreak` (1 hour) between two commands after it (`openFailures`). A failure that is the latest command always shows. The digest and the suggestion candidates leave out every failure that is not open (`withoutSettledFailures`), and the answer of Where Did I Leave Off names only the card's failure.
- **`project memory <project> [--set on|off|forget] [--panel show|hide]` is DEBUG only.** `--set on` records without Apple Intelligence (`modelReader` answers `.available`, and `--set off` gives it back), because no CI runner has it; the summary still asks the real model. It reads the redacted entries, the unresolved failure, the suggested rows and the summary's phase and text, shows or hides the key window's panel, and `--summary write` writes the summary now. `scripts/e2e/test_project_memory.py` prints OSC 133;C with `cmdline_url` and OSC 133;D from a script, because CI's bash 3.2 has no shell integration.
- **The App Intent "Where Did I Leave Off"** (`GetMactermProjectMemoryIntent`) returns the answer as text and as a dialog, so Siri says it. `ProjectMemoryAnswer` (pure) composes it: the stored summary with its backticks dropped, then the latest command when it finished after the summary was written; without a summary, the latest command with its result and the unresolved failure. **It never writes a summary**: the background summary (after the quiet period, or at once for a project's first summary) and the panel's button stay the only writers, so the intent answers at once. It refuses with `MactermIntentError.unavailable` below macOS 26, without Apple Intelligence (with the reason), while memory is off, and for the pinned and scratch workspaces. It reads the memory through `MactermIntentHost.projectMemory`, so a test hands in a memory on a temporary store.
